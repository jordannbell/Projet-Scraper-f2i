# Seekra - Backlog 30/60/90 jours

## Hypotheses

- Priorite go-to-market: France B2C + premier socle B2B.
- Equipe cible: 1 fullstack principal + 1 support part-time (product/ops).
- Objectif: MVP vendable en 90 jours avec fondations de scale.

## J0-J30 (stabilisation revenue + fiabilite coeur)

### Sprint 1-2
- Implementer billing Stripe complet (checkout + webhooks + mise a jour plan).
- Ajouter middleware d'entitlements backend (free/starter/pro/elite).
- Unifier auth guard frontend/backend (routes protegees coherentes).
- Finaliser flux auto-apply sans doublons (queue idempotente + transitions atomiques).

### Sprint 3-4
- Rendre tracker utilisable: statuts clairs, filtres, pagination, exports CSV simples.
- Corriger i18n critique (login/register/dashboard/auto-apply/matches).
- Normaliser UX erreurs/loading (toasts uniques, codes erreur backend standardises).

### Livrables J30
- 1er flux payant fonctionnel.
- Auto-apply stable sur plateformes supportees.
- Parcours user complet inscription -> 1ere candidature.

## J31-J60 (beta privee et hardening produit)

### Sprint 5-6
- Matrice plateforme auto-apply (auto complet / semi-auto / manual guide).
- Tracker v2: timeline, notes, premiere relance assistee.
- Dedup offres inter-sources robuste (hash metier + contraintes DB).

### Sprint 7-8
- Observabilite v1: logs structures, dashboard erreurs, alerting P0.
- CI/CD v1: pipeline lint/test/build + deploy staging + smoke tests.
- RGPD v1: export donnees compte + suppression compte orchestration backend.

### Livrables J60
- Beta privee exploitable (50-100 users).
- Incidents monitorables.
- Base legale/compliance minimale.

## J61-J90 (go-live public + fondations B2B)

### Sprint 9-10
- Modules business: historique facturation, page plan, downgrade/upgrade self-service.
- KPI produit: activation, conversion free->paid, taux applied/needs_manual.
- Performance: budget API + cache endpoints lourds.

### Sprint 11-12
- Fondations B2B v1: organisations, memberships, roles basiques.
- Entitlements B2B (plan au niveau organisation).
- Runbooks incidents + checklist go-live + drill rollback.

### Livrables J90
- Lancement public controle.
- MRR traçable.
- Process ops minimum viable pour croissance.

## Dependances critiques

- Stripe webhooks depend du modele DB subscription/entitlements.
- B2B depend de la migration data org_id.
- SLO/alerting depend de la normalisation logs/metrics.

## Estimation macro (effort relatif)

- Billing + entitlement: **L**
- Auto-apply reliability: **L**
- Tracker + UX + i18n: **M**
- CI/CD + observabilite: **M**
- RGPD workflows: **M**
- B2B foundations: **L**

## Definition of done (MVP vendable)

- Paiement actif et quotas correctement appliques.
- Au moins 1 source avec auto-apply reel stable + autres sources en mode explicite.
- Tracker utile pour suivre l'etat des candidatures.
- Alertes erreurs critiques en place.
- Support legal minimal (CGU, export/suppression donnees).
